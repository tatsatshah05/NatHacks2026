# OP-107: Construction sidewalk closures

Work for [issue #35](https://github.com/tatsatshah05/NatHacks2026/issues/35),
targeting the team's `phase_1` branch. The adapter and offline tests are ready
for review; the shared API/store/scheduler have not landed on this base yet.

## Run it

From the repository root in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r cloud/tests/requirements-construction.txt
.\.venv\Scripts\python.exe -m cloud.app.adapters.construction --fixtures cloud/tests/fixtures/construction --at 2026-11-07T19:00:00Z
.\.venv\Scripts\python.exe -m pytest cloud/tests -q -p no:cacheprovider
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\ruff.exe format --check .
```

The recorded preview is labelled `mode: replay`. `--at` is only available for
recorded data and must include a timezone. For a one-shot live read use:

```powershell
.\.venv\Scripts\python.exe -m cloud.app.adapters.construction --live
```

Set `SOCRATA_APP_TOKEN` in your shell for Socrata access; `.env.example` contains
the blank template. The standalone CLI does not load `.env` automatically.
Never commit the token.
Anonymous public reads can be throttled. The CLI reads data and prints results;
it does not start the full app, write to a database or run a background job.

## Behavior and source limits

- Uses the official [On-street Construction and Maintenance dataset](https://data.edmonton.ca/d/7wiq-4rgy)
  (`7wiq-4rgy`). The City describes `start_date` as the proposed start and
  `finish_date` as the estimated finish. The issue's rule treats pedestrian
  impacts as closures; the title says "Construction affects pedestrians" rather
  than claiming a separately verified complete sidewalk closure.
- Filters `pedestrian_affected = Yes` and dates active **today in Edmonton**.
  Start and finish dates are inclusive calendar dates. Output `ends_at` is the
  start of the following day, converted to UTC. `No`, `Unknown` and unspecified
  pedestrian flags do not create blocks. Future and expired permits are skipped.
- Uses `geometry_multiline` only when its **total** length is under 500 m and
  every component passes within 30 m of the City's permit point. Length uses
  spherical segment distances; proximity uses distance to the segment interior
  in a local metre projection. These limits implement Tatsat's PR #88 review.
  A long, distant or malformed line falls back to `location` (Point), then the
  latitude/longitude pair, with a warning. No midpoint is invented. A line
  without a point cannot be verified and is omitted with a warning. The recorded
  P2024-003729 corridor measures about 18.16 km and now uses only its permit points.
- Some official pedestrian permits have no coordinates or geometry. They cannot
  be attached to a route. The preview includes explicit warnings identifying
  those permits and omits them from the map. The scheduler integration must
  expose these warnings as data quality diagnostics; do not silently discard them.
  Malformed rows are skipped and logged individually, including invalid dates,
  missing required fields and non-object rows. Valid neighbouring rows still
  update. Previous records for affected permits remain at their original
  `observed_at`/`expires_at`; an unidentified bad row conservatively preserves
  otherwise missing previous records. No retained record is made fresh. Warnings
  are returned in the preview/result and exposed through `last_error`.
- A permit can cover multiple road segments. `source_ref` combines the permit
  number with a deterministic hash of street, intersections and geometry.
  Distinct segments remain separate; identical duplicates collapse. Conflicting
  duplicates log a warning and select the latest finish date, then latest start
  date, then fullest detail (lexical tie-break), independent of row order.
  IDs survive input ordering, date extensions and reason edits. A geometry change creates a
  different ID; confirm source snapshot reconciliation with the shared store.
- Outputs the fields in PLAN.md section 10: `category: sidewalk`,
  `kind: sidewalk_closed`, `effect: blocked`, high official-source confidence,
  source URL and City of Edmonton Open Data attribution.
- Reads all pages in a deterministic order, with a ten-second timeout per request.
  Each page is requested once. There are no internal sleeps, retries or polling
  gates; OP-103 owns hourly scheduling, retry backoff and failure cooldowns.
  The caller can fetch immediately again, including at local midnight.
- The helper retains last-good data in memory and raises `FeedError` for failed
  reads, invalid JSON or a non-array envelope. Those source failures never replace
  the saved snapshot. Row-level errors are diagnostics, not source-wide failures.
  A genuinely empty successful feed clears old permits. The cache does not
  persist across restarts.
- There is no per-record observation timestamp in this dataset. `observed_at`
  records the successful fetch time. The provisional expiry is three hourly
  cycles, capped at the finish-day boundary, consistent with the scheduler's
  three-missed-cycle stale rule. Confirm expiry during shared integration.
