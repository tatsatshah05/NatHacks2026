# OP-205: Camera and weather ice risk

For [issue #48](https://github.com/tatsatshah05/NatHacks2026/issues/48), targeting
`phase_2`. `cloud/app/camera_ice.py` evaluates confirmed camera evidence and
OP-109's weather watch, then matches local ice risk to OP-104 crossing edges.
It creates existing shared `Obstruction` records at medium confidence.

**Prepared for integration, not wired into the live API or router.** OP-204's
camera-ingest payload/receiver and the OP-206/207 handoff remain pending. This
branch changes no shared schema, endpoint, configuration or routing weights.

## Rules

All camera evidence must be unexpired, not future-dated, and in the application's
live/replay mode. Pass only confirmed OP-204 outputs, after its model confidence
gate and two-observation stability filter; raw model guesses are not inputs.

| Camera evidence | Weather evidence | Local ice risk |
| --- | --- | --- |
| `ice` | Any, including unavailable | Yes, at medium confidence |
| `wet` | Fresh active watch, freezing air or ground | Yes, at medium confidence |
| `wet` | Inactive watch | No |
| `wet` | Both air and ground above zero, even if active flag is inconsistent | No; diagnostic for inconsistency |
| `wet` | Missing, stale, future or wrong-mode watch | Uncertain; no new hazard or clear instruction |
| `dry`, `snow_partial`, `snow_covered` | Any | No ice-risk record; snow handling remains separate |
| `unknown`, `unusable` | Any | Uncertain; no new hazard or clear instruction |

Zero degrees counts as freezing. An active watch still comes from OP-109's full
moisture/melt/frost rule; freezing temperature by itself is insufficient for a
wet reading. A city-wide watch without a wet/ice camera never creates a local
routing hazard. Wording is always "ice risk", never a claim of detected black ice.

## Inputs, freshness and recovery

`CameraEvidence` is a local validated projection of OP-204's proposed reading,
not a new shared contract. It accepts worker objects or their dictionaries and
reads `source`, `source_ref`, `label`, `latitude`, `longitude`, `observed_at`,
`expires_at` and `mode`. Additional model/view fields are ignored. The exact
ingest handoff still requires Tatsat's agreement. Times must include a timezone;
nonfinite/out-of-range coordinates, invalid lifetimes and blank IDs are rejected.
One malformed row cannot discard valid neighbours.

Use `match_service_camera_ice()` with the real `WeatherService` where possible.
It automatically passes the retained watch and the service's stale flag. For
isolated callers, `match_camera_ice()` accepts `WeatherResponse` plus
`weather_stale`; the public weather response has no stale field. Wet readings
also enforce OP-109's existing two-hour provider observation limit. A recent
cached active watch with a failed refresh is not used as fresh evidence.

The result preserves the camera's observation time. Ice-only expiry is the
camera expiry; wet-plus-watch expiry is the earlier of camera expiry and the
watch observation's age limit. Re-evaluating weather never makes old camera
evidence fresh. Wet risk attributes 511 Alberta, Environment and Climate Change
Canada, and Open-Meteo; ice-only risk attributes its camera source.

Keep the newest reading per source reference. Identical duplicates collapse;
contradictory records with the same timestamp are uncertain in either order.
Newer dry evidence supersedes older ice evidence. Source references remain
stable across refreshes: obstruction IDs are `camera_model:<camera_ref>:ice_risk`.

## Crossing matching and routing handoff

Build `CrossingIndex(network)` once at startup, rebuilding when the network
changes. It selects only `EDGE_CROSSING` edges using OP-104's flag constant and
indexes every polyline segment. Per-camera distance calculations are vectorised
in NumPy using a local metre projection. No geocoder, external request or graph
rebuild occurs at route time.

The radius is **50 m inclusive**, measured to the nearest point on the full
polyline, including bends and segment interiors. An adjacent ordinary sidewalk
is never selected merely because it is close to the camera. Geometry uses the
network's stored float32 coordinates, so boundary accuracy is limited by that
data; no extra geographic buffer is added. An unlocated/malformed crossing is a
network-data problem, not permission to match unrelated paths.

`CameraIceResult` contains:

- `mode`: explicit live/replay provenance, which must match the caller's app.
- `risks`: shared obstruction records paired with exact `edge_indices`.
- `by_edge()`: edge index to obstruction tuple, ready for the matcher/router to
  translate to its hazard objects. Overlapping cameras retain separate evidence;
  the router applies its existing strongest-effect rule, not multiplied risks.
- `warnings`: unavailable evidence, malformed/conflicting rows or no crossing
  within 50 m. An unmatched camera must not affect arbitrary nearby footways.
- `clear_refs`: only camera references with current affirmative non-risk evidence.
- `uncertain_refs`: known references whose current state cannot be established.

The Point geometry identifies the camera, not a generic obstruction-match radius.
**Use the supplied crossing indices; never feed these points into the generic
point matcher**, which could tag ordinary sidewalks or miss crossings 30–50 m
away. OP-206/207 must explicitly consume this result. Existing blocked barriers,
profile costs, maximum-overlap rules and city-wide caution remain unchanged.

This helper does not upsert or delete anything. The ingest/store integration
must only clear the corresponding local ice record for an explicit `clear_refs`
entry. Missing rows, warnings and empty `risks` do not instruct bulk deletion.
Keep previous uncertain records only until their original expiry; do not renew
them or present them as confirmed clear. The weather watch remains a separate
city-wide advisory. No source or state is persisted by this helper.

## Verify it

From the repository root after installing the repository requirements:

```bash
python -m pytest cloud/tests/test_camera_ice.py -q
python -m pytest -q
ruff check .
ruff format --check .
```

Tests use synthetic readings/networks and the committed city network. No camera
frames, trained model, API key or external HTTP is required. They cover every
rule branch, source failure/recovery, mode and freshness boundaries, 49/50/51 m
distances, curved crossings, ordinary-sidewalk exclusion and unchanged graph data.
