# OP-204: Camera vision worker

For [issue #47](https://github.com/tatsatshah05/NatHacks2026/issues/47), targeting
`phase_2`. The worker fetches camera frames, runs CPU ONNX inference in memory,
stabilises conditions and can post metadata to the planned ingest endpoint.

**Status: prepared for integration, not a completed live camera service.**
OP-202's trained export is pending. Tatsat accepted the payload and implemented
the receiver in OP-213 (`op-213-camera-ingest`, checked at `b7901e7`); that branch
is not merged on this base yet. A local in-process check accepts the exact worker
JSON, returns it from `GET /api/cameras`, and rejects a wrong placeholder key.
Shared schemas, API routes and `config/` are unchanged here. No worker deployment
is activated.

## Run it

After installing the repository requirements, from the repository root:

```bash
python -m vision.worker
```

`make worker` runs the same command. It prints `mode: replay` and
`synthetic_predictions: true` using `vision/tests/fixtures/worker_replay.json`.
It exercises voting from synthetic predictions, not measured model output.
It needs no keys, HTTP requests, images or model, and never posts data.
On Windows, use `.venv\Scripts\python.exe` instead of `python` if needed.

```bash
python -m pytest vision/tests/test_worker.py vision/tests/test_worker_inference.py vision/tests/test_worker_review.py -q
python -m pytest -q
ruff check .
ruff format --check .
```

For live operation after the model/image dependencies are ready, set
`ALBERTA_511_KEY` and `MODEL_URL`. Obtain `labels.json` from Ipsa's training
export. Replace the checksum and score placeholders below with the published
asset checksum and a threshold agreed from validation; no default is invented:

```bash
python -m vision.worker --live --model-labels /path/to/labels.json --model-sha256 EXPECTED_SHA256 --min-score VALIDATED_SCORE --once
```

This performs one pass without posting. Initial conditions need two agreeing
observations, so the first pass normally has no confirmed readings. Omit
`--once` for continuous operation; a non-publishing run logs condition changes.
`DATA_MODE=replay` prevents live operation.

After the OP-213 endpoint is merged and deployed, set `CLOUD_URL` and
`WORKER_KEY`, and add `--publish` to send live readings. No replay is posted.
Run one worker per 511 key: separate processes do not share the memory limiter.
Use `--boundary /path/to/edmonton.geojson` for an exact city boundary; otherwise
OP-112's approximate bbox includes some neighbouring areas.

## Scheduling, freshness and failures

- Refresh the camera list daily. On failure use OP-112's last-good metadata and
  retry next pass. One shared sliding-window limiter covers every metadata and
  image request, enforcing 10 calls in any 60 seconds. HTTP 429 on either path
  pauses the shared limiter for a full minute. The
  [511 developer documentation](https://511.alberta.ca/developers/doc) states
  this limit. Model downloads and API posts are separate requests.
- Process views serially, then wait `--interval-s` (default 300 seconds).
  Actual per-camera cadence includes pass duration; no catch-up burst occurs.
  The default is provisional, not a measured coverage or latency guarantee.
- Request only HTTPS view URLs on `511.alberta.ca`, with no redirects. Accept
  JPEG/PNG responses, bounded to 8 MiB and 10 million decoded pixels, with a
  20-second request timeout. The
  [official camera API](https://511.alberta.ca/help/endpoint/cameras) exposes
  view URLs, not a separately documented still-image endpoint. HTML viewers,
  redirects and other formats produce `unknown`; never scrape or derive a
  private URL. One direct JPEG is verified above; additional view coverage and
  availability still need verification. City camera streams are not used.
- Maintain independent state per camera/view. Initial and changed labels need
  two agreeing observations. A single different observation never renews the
  saved condition. Emit one log line per confirmed change.
- The most recent 32 distinct good-frame hashes per view cannot confirm or
  renew a reading, including alternating cached stills. Failed attempts never
  evict those hashes. Failed,
  disabled or unusable attempts vote `unknown`; two attempts confirm it. A
  single clear frame cannot clear unavailable status. No previous `dry` reading
  is made fresh by an offline/uncertain observation.
- Reject darkness/very low contrast before inference. On a 64x64 greyscale
  preview, mean below 16 or a 10th-to-90th percentile range below 12 is rejected.
  These are provisional conservative guards, not validated fog detection.
  OP-202 must also recognise real fog, offline placeholders and obstructions as
  `unusable`. That class, low score, invalid output and model errors map to
  `unknown`. No real-world accuracy or under-200-ms performance is claimed.
- POST metadata with `X-Worker-Key`, a 10-second timeout and no redirects.
  Failed posts retain the last acknowledged reading. Retry pending metadata on
  a later pass even if its frame is unchanged, without changing its timestamps;
  never resend an expired pending reading. Its removal logs one
  `CHANGE ... expired undelivered` line.
- `--once --publish` reports requested/attempted/succeeded/failed post counts and
  sets `published` only after delivery. It exits non-zero when posts were
  attempted but all failed. A first pass awaiting two-observation confirmation
  exits normally with zero attempts and `published: false`. A non-publishing preview
  exits normally and never claims a post occurred.
- The live worker passes OP-112's `DEFAULT_CACHE_PATH`, allowing a restart to
  use persisted last-good metadata during a catalog outage. Only metadata is
  cached; vote hashes and reading/delivery state remain in memory.
- Provisional expiry is three configured intervals. Agree this policy against
  the effective camera count/cadence; the API must enforce expiry and show stale
  or unavailable information. State is currently in memory, not restart-persistent.
- No frames are saved or sent to the API. Model weights are downloaded once into
  memory (128 MiB cap), checksum-verified and reused. The classifier uses the
  [ONNX Runtime CPU API](https://onnxruntime.ai/docs/api/python/api_summary.html).
  Keys, images, arrays and raw HTTP/native model exceptions are not logged.

## Model handoff from OP-202

The worker reads the existing `labels.json` format written by
[OP-202 at f8879bf](https://github.com/tatsatshah05/NatHacks2026/commit/f8879bf).
It does not import PyTorch or require a second metadata export format.

| Field | Meaning |
| --- | --- |
| `classes` | All six LABELS.md classes once, in actual output order |
| `input.name`, `output.name` | Actual tensor names (`image` / `logits` in the export) |
| `input.size_px` | Square input dimensions, checked against ONNX metadata |
| `input.color`, `input.layout` | `RGB`, `NCHW` |
| `input.resize`, `input.scale` | `stretch to size_px x size_px`, `pixel / 255` |
| `input.mean`, `input.std` | Training-time three-channel normalisation; positive std |
| `output.softmax` | `apply in the worker`; logits must have shape `[1, 6]` |

`--model-sha256` and `--min-score` are separate explicit worker settings, because
the current training export contains neither. Internal `ModelSpec` validates
the settings and rejects nonfinite values. Changed transforms fail explicitly
instead of silently mismatching training. Confirm the final release with Ipsa.
No trained weights are invented here. Tests generate a tiny ONNX graph and
synthetic images in memory; they verify plumbing, not real road recognition.

## Agreed OP-213 ingest payload

`Reading` serializes the shape accepted by Tatsat's OP-213 receiver. POST one
object to `/api/ingest/camera` with these fields:

| Field | Meaning |
| --- | --- |
| `source`, `source_ref` | `camera_model`, stable `511:<camera_id>:<view_id>` |
| `camera_id`, `view_id` | Official camera and view identifiers |
| `latitude`, `longitude` | Camera coordinates, not an invented crossing location |
| `label` | `dry`, `wet`, `snow_partial`, `snow_covered`, `ice` or `unknown` |
| `score`, `reason` | Model score when available; worker reason code |
| `observed_at`, `expires_at` | UTC sample time and provisional expiry |
| `model_version` | Exact model asset SHA-256 |
| `mode` | `live` for posting; local replay is `replay` |
| `attribution` | Road camera data: 511 Alberta, Government of Alberta |

No image bytes or keys belong in the body. The key is an HTTP header only.
OP-205 separately combines camera/weather evidence into local `ice_risk`.
This worker does not change routing costs or claim black ice was detected.

The exact JSON shape is in [OP-204-request.example.json](OP-204-request.example.json).
It is a synthetic example with a placeholder model hash, not a real camera/model
result or a request to send to a live service.
